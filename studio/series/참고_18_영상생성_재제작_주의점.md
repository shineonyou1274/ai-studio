> 편집 규칙은 `0_편집_원칙.md`, 얼굴 기준은 `../0_1UP_기준.md` 21번, 소스 판정은 `16_풀뮤비_소스목록.md`.

## A. 영상을 새로 뽑을 때

### A-1. 뽑기 전
1. **얼굴 기준을 먼저 정한다.** 원래 준 = f1_tie·f6(흉터, 노란 아이라인, 귀걸이, 검은 옷). 새 멤버 = 흰 셔츠 이어폰 남자 hvE(흉터·화장 없음). 린 = EP.1 얼굴 f4·n1(노란 날개 아이라인, 긴 웨이브 머리).
2. **새 얼굴 이미지(시트)를 만들어 기준으로 쓰지 않는다.** 대조를 통과한 기존 컷의 실제 화면을 첫 장면으로 넣는다. (EP.2 N4~N10: 새로 그린 얼굴 시트를 기준으로 뽑았더니 남자는 매력 없는 다른 얼굴, 린은 못생긴 다른 얼굴이 됨. 손 컷만 살아남음)
3. **이름표를 믿지 않는다.** `JOON_인스타게시본_얼굴`, `02_JOON_처음선택_남자2.png`는 EP.1 준과 다르다. 파일 이름이 아니라 대조판으로 확인한다. (f1·f6을 두 번째 파트너로 잘못 기록 → 사장님 정정 "처음준은 EP1 아니야")
4. **다른 얼굴 계열 폴더를 클로즈업에 쓰지 않는다.** `10_하이라이트_영상`·`뮤비1_컷`·`재생성`은 다른 계열. `재생성` 흰옷 컷은 남자 뺨에 원래 준의 흉터가 남아 있어 새 멤버로 못 쓴다.
5. **한 컷에 한 가지 동작만.** 5초 안에 두 가지를 시키면 뒷부분이 무너진다. (N8 아이라인: 3.8초 뒤 양쪽 눈이 갑자기 노래짐)

### A-2. 프롬프트에 꼭 넣는 금지
- 목줄·출입증·이름표, 흰 장갑, 손목시계, 화면 속 글자·숫자·간판·뭉개진 글씨
- 빨강(레드카드 구간 141–153초에만 편집으로 입힘), 바닥의 노란 선
- 피·상처·수술 도구 클로즈업, 눈·병원 장면의 자극적 묘사(안전 필터에 걸림)
- 탱고·포옹 같은 큰 춤 동작. 춤은 최소로, 리듬만
- 이상한 소품(수도꼭지 분수, 사람보다 큰 트로피)

### A-3. 비용과 승인
1. **견적 → 사장님 승인 → 생성.** 승인은 묶음 단위로, 최대 크레딧을 먼저 말한다. TTS 1크레딧도 마찬가지다. (v4에서 앵커 목소리를 승인 없이 뽑지 않은 것이 맞았다)
2. **저화질 먼저.** 480p로 뽑아 얼굴을 대조한 뒤 통과한 컷만 720p로. 처음부터 고화질로 뽑지 않는다.
3. **얼굴이 가장 걸리는 컷 2~3개를 먼저** 뽑고 대조한 뒤 나머지를 뽑는다. 한 번에 전부 뽑지 않는다.
4. 예산 한도(풀 뮤비 750) 안에서 **다시 뽑을 몫을 남긴다.**

### A-4. ZCRE 사용법 (실수했던 것)
- `quote` → 같은 `idempotency_key`와 같은 입력으로 300초 안에 `create_generation`. 입력을 바꾸면 견적을 새로 받는다.
- `agent_quote_invalid`가 나오면 같은 키·같은 입력으로 다시 견적. 새 키로 바꿔 중복 생성하지 않는다.
- 결과 확인은 `status`·`outputs`로. 진행 상태를 보려고 새로 생성하지 않는다.
- nano-banana-pro 참조 편집은 요청 하나에 결과 하나뿐.
- 안전 필터로 실패한 요청은 과금되지 않는다. **같은 내용을 다시 시도하지 않고** 다른 컷으로 대체한다. (N1 눈 뜨는 장면)
- 동시 생성 제한에 걸리면 기다렸다가 제출한다.
- 내려받는 링크(서명 URL)는 사장님께 보여 주지 않는다. 비밀 값은 채팅으로 받지 않는다.

### A-5. 뽑은 뒤 (반드시)
1. **프레임을 0.25초 간격으로 펼쳐서** 끝까지 본다. 뒷부분에서 무너지는 경우가 많다. (아이라인 양쪽 눈)
2. **얼굴 대조판**을 만든다: 기준 컷 화면과 새 컷 화면을 나란히. 흉터·아이라인·옷·얼굴형을 확인한다.
3. 손가락 수, 장갑, 시계, 글자, 소품, 창백한 피부를 확인한다.
4. 쓸 수 있는 구간을 초 단위로 기록한다(`16_풀뮤비_소스목록.md` 형식).

## B. 편집하고 다시 만들 때 (내가 했던 실수)

### B-1. 소리
1. **노래를 잘라 붙이지 않는다.** 길이는 컷으로 맞춘다. (EP.2 v5: 130→137초 이음매와 멈춤 있는 마디에서 시작한 것이 "판 튀는 소리"로 들림)
2. **원곡에 원래 있는 멈춤**(Yellow card 박자 끊기 다섯 곳, "경고는 여기까지" 세 번)은 편집 실수가 아니다. 남의 지적을 그대로 믿지 말고 원곡 파형과 대조한다.
3. **목소리를 빠르게 돌리지 않는다.** 1.12배에서 경박해졌다. 줄여야 하면 문장을 겹치거나 뺀다.
4. EP.1에서 쓴 목소리는 **자르지 말고 그대로** 이어 쓴다. 이야기 흐름이 끊긴다. (사장님 "앞의 것 그대로 쓰면 되잖아")
5. 말소리는 배경보다 12dB 이상 크게. 노래는 앵커 아래로 작게 깔았다가 드롭에서 제 음량.
6. 효과음은 꼭 필요한 것만. (툭툭 소리, 피아노 세 음: 사장님이 빼라고 함)
7. 끝은 칼로 자르지 말고 잔향으로 마감한다.

### B-2. 화면 처리
1. **색 빼기·보정 처리는 장면마다 결과를 원본과 나란히 본다.** (손목밴드 탈색이 노을빛까지 회색으로 바꿔 얼굴 가장자리에 얼룩 → 사장님이 "화질이 안 좋다"고 봄)
2. 3D 모션그래픽을 넣기 전에 그 시각의 프레임을 먼저 본다. 경고 테이프·"출입 금지"·막대그래프가 섞여 있다.
3. 자막 페이드에 검은 테두리가 생기면 미리 곱한 알파(premultiplied)로 흐림을 건다.
4. 흰 배경(이불·셔츠) 위 흰 자막은 그림자를 넓고 진하게. 한 줄이 화면 폭을 넘으면 두 줄로.
5. 자막은 한 번에 한 문장. 같은 문장을 본편과 카드에 두 번 띄우지 않는다.
6. 소품 오류는 확대(크롭)로 가린다. 가릴 수 없으면 그 컷을 뺀다.
7. 최종 압축은 crf 25 안팎. 27은 얼굴이 뭉개지고 21은 파일이 너무 크다(58MB).

### B-3. 컷 구성
1. **같은 컷을 두 번 쓰지 않는다.** 기억 플래시 0.3초 이하만 예외. 다 붙인 뒤 소스·구간 겹침을 자동 검사한다.
2. **처음 보는 사람 기준으로 확인한다.** 설명을 전혀 주지 않은 에이전트에게 영상만 보여 주고 "무슨 이야기인지, 남자가 몇 명인지" 묻는다. (EP.2 v2: 나는 "지금의 새 멤버"로 넣었는데 처음 본 눈은 "교복풍 과거 추억"으로 읽음)
3. 기억과 지금이 헷갈리면 컷을 더 넣지 말고 **린의 속마음 자막**으로 풀어 준다.
4. 핵심 장면은 짧고 정확하게. 4초 정지 화면은 이탈 구간이 된다.

### B-4. 일하는 방식
1. **고치기 전에 이전 빌드 코드를 `build_*_v이전.py`로 보관**하고, 영상 이름도 버전을 올린다.
2. 다 만들면 **프레임 확인 → 음량 수치 확인 → 커밋·푸시 → 사장님께 파일 전송** 순서. 소리는 내가 들을 수 없으니, 수치로만 확인했다고 말하고 직접 들어 봐 달라고 한다.
3. **제미나이·메타 의견은 그대로 따르지 않는다.** 사실관계(음원이 우리 곡인지, 반복 편집이 있는지, 정지음이 있는지)를 먼저 확인하고, 틀린 지적은 틀렸다고 말한다. 맞는 지적만 반영하고 반영하지 않은 것은 이유를 적는다.
4. 사장님이 직접 넣으라고 한 것을 빼자고 할 때는 **먼저 묻는다.**
5. 커밋 메시지에 모델 이름을 넣지 않는다. 작업 브랜치는 `claude/festive-wright-vjugcc`만. 저장소는 비공개 유지.
6. 배운 것은 바로 이 문서나 `0_편집_원칙.md`에 적는다.
