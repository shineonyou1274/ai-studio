## GATE S13 — 프레임: 가로 / 세로 ★ (제일 먼저 선택)

**왜:** 프레임이 화각·구도·자막·미술을 전부 규정한다. **한 번 정하면 전 씬에 고정**되므로 맨 먼저 잠근다. (사용자 절대 요구: "가로영상을 만들 것인지 세로영상을 만들것인지 먼저 선택")

> 📚 강의: 슬라이드7·「스크린이 줄수록 얼굴이 커진다」 — S1-Q4의 시청 계약이 기본값을 정한다: 모바일 피드(A) = 세로, 시사·상영(C) = 가로. **세로를 고르면 물리 법칙 3종이 따라온다: 표정이 정보의 전부(반신~CU 위주) · 자막 상시(절반은 무음 시청) · 와이드 최소화(정보가 사라진다).**

### Q13-1. 프레임 (객관식)
| 선택 | 비율 | 어울리는 것 | 구도 규칙 |
|---|---|---|---|
| A. **가로 16:9** | 1920×1080 | 시네마틱 정극·풍경·투샷·와이드 | 3분할·헤드룸·리드룸, 와이드/미디엄 자유 |

## GATE S14 — 대사 장면 / 인서트 장면 분류

**왜:** 씬을 두 종류로 나눠야 화각·호흡·영상 처리가 갈린다. (사용자 요구: "대사가 들어가는 장면과 인서트 장면들을 나눠주고")

### 정의
- **대사 씬(Dialogue)**: 인물이 말하는 씬. 립싱크·음성 일관성이 걸린다(STAGE 4의 Voice Sheet 대상). 화각 = 3/4·OTS·리액션 CU 위주(정면 립싱크 최소화).
- **인서트 씬(Insert)**: 대사 없는 컷 — 소품 매크로, 공간, 손, 시선, 상징 오브제, 전환용 이미지. **립싱크 리스크 0**, 셋업/페이오프·리듬·정서의 핵심.

### Q14-1. 에이전트가 씬 리스트를 자동 분류 → 사용자 확정
- 씬 카드의 `대사 유무` 필드로 1차 분류 후, 애매한 씬은 사용자에게 확인.
- **각 대사 씬에는 '누가 말하나'(화자)를 태그** → STAGE 4에서 그 인물의 Voice Sheet가 걸린다.
- **인서트 씬 비율 점검:** 인서트가 너무 적으면(전부 대사) 리듬이 밋밋하고 립싱크 부담↑. 에이전트가 "여기 인서트 1컷 추가 제안"을 낼 수 있다(셋업/페이오프 오브제 등 — 취향 태그 활용).

### Q14-2. 인서트 활용 강도 (객관식)
- A. 최소(대사 위주 정극) / B. 균형 [기본] / C. 인서트 리치(몽타주·상징 많이 — 시적/느린 취향)

**산출물:** 씬별 `[대사|인서트]` 라벨 + 대사 씬 화자 태그.

## GATE S15 — 호흡: 타이트 / 슬로우

**왜:** 같은 씬 리스트도 호흡에 따라 완전히 다른 드라마가 된다. (사용자 요구: "타이트한 호흡과 천천히 흘러가는 호흡을 선택")

### Q15-1. 전체 기본 호흡 (객관식)
| 선택 | 호흡 | 컷 길이·수 | 카메라 | 어울리는 것 |
|---|---|---|---|---|
| A. **타이트** | 몰아치는 | 짧은 컷 다수, 컷당 1.5~2.5s | 빠른 단일 무브·매치컷 | 스릴러·사이다·긴장 |
| B. **슬로우** | 천천히 흐르는 | 긴 컷 소수, 컷당 4~8s 홀드 | 느린 무브·롱테이크·정지 | 정극·휴먼·시적 여백 |
| C. **혼합(비트별 지정)** [추천] | 구간마다 다르게 | 비트 따라 | 상승=타이트, 정점·여운=슬로우 | 대부분의 드라마 |

### Q15-2. (C 선택 시) 비트/구간별 호흡 배정
- 에이전트가 비트시트에 호흡을 매핑해 제안(예: 압박 상승=타이트, 반전 직후 여운=슬로우). 취향 태그(`#여백`)가 붙은 씬은 슬로우 우선.
- **호흡은 씬 카드에 `pace: tight|slow`로 기록** → STAGE 4 영상의 컷 길이·카메라 무브·홀드가 여기서 결정된다.

> **작법 연결:** 명작의 편집 리듬 원리 — "빠른 구간과 멈춘 구간의 낙차 자체가 리듬"(몽타주 속사포 vs 대치 롱테이크). 균일한 호흡은 밋밋하다. 정점 직전 슬로우 → 정점에서 타이트, 또는 그 반대의 낙차를 설계. **절제 컷은 무표정 CU를 2.5~3초 길게 홀드, 폭발 시퀀스는 1초 안팎 속사포**(절제→폭발의 컷 길이 문법). 📚 강의: 슬라이드42
> **[숏폼 트랙] 재계약 리듬** 📚 강의: 슬라이드4~6·59: 시청자는 3초마다 재계약한다. **90~150초마다 마이크로 3막(사건 제기→떡밥→직전 끊기)이 한 바퀴** 돌게 씬 호흡을 배치하고, 클리프행어는 사건형뿐 아니라 **감정형**(표정이 무너지는 얼굴에서 컷)도 쓴다.

**산출물:** 씬별 `pace` 값.

## GATE S16 — 480p 나노바나나-라이트 전 씬 프리뷰 HTML + 셀렉터 ★

**왜:** 고화질을 뽑기 전에 **전체 스토리보드를 저비용으로 한눈에** 보고 방향을 잠근다. (사용자 요구: "제대로 생성하기 전에 나노바나나라이트를 활용해서 480p의 저화질로 전체 스토리보드를 볼수 있는 html 페이지")

### 16-1. 480p 초벌 생성 (저비용 드래프트)
- **모델**: 나노바나나-라이트(= `nano_banana_2`의 저해상·드래프트 모드). 호출 전 `models_list`/`models_explore(action='get')`로 저해상 라벨(480p 상당)·파라미터를 확정한다.
- **프롬프트**: 씬 카드(장소·인물·행동) + 프레임 비율(S13) + 취향 태그. **이 단계는 캐릭터 시트 락을 걸지 않는다**(아직 시트 미생성) — 대신 인물 묘사를 텍스트로만. 초벌의 목적은 **구도·앵글·미술 방향 확인**이지 얼굴 일관성이 아니다.
- **비용·속도**: 저해상이라 씬당 비용·시간이 낮다. 전 씬을 **백그라운드 에이전트**로 배치 생성(동시 한도 준수, 폴백: 순차+체크포인트). 4종 프리뷰 승인 후 실행. **480p 프리뷰는 양 모드(QUALITY/ECO) 공통** — 이 단계가 크레딧 절약의 핵심 장치다("싼 것으로 방향, 비싼 것으로 완성"). 방향 실험은 전부 여기서 끝낸다.

> **4종 프리뷰(승인 필수):** MODEL=나노바나나-라이트(480p) / 해상도=480p 드래프트 / 오디오=N/A / 비율=S13. + 씬별 프롬프트 요약 테이블(한글) + **"PREVIEW_DRAFT 주입됨"** 표기. (S16 시점엔 캐릭터 시트·화각 배정·조명 레시피가 아직 없으므로 규칙0[A] 전체가 아니라 `06`의 **S16 전용 축약 상수 `PREVIEW_DRAFT`**(프레임·심도·ARRI 룩만)를 쓴다.)

### 16-2. 프리뷰 HTML 빌드 (`_build_storyboard_preview.py` — 스케치)
- 각 480p png를 **Pillow로 리사이즈 → JPEG q70 → base64**로 박아 **자체완결 HTML 1파일**(외부 이미지 의존 0).
- **레이아웃**: 프레임 비율에 맞춘 카드 그리드(가로=16:9 카드, 세로=9:16 카드). `#0b0d12` 다크.
- **카드 구성**:
  - 480p 썸네일 + 씬번호(S07) + `[대사|인서트]` 배지 + `pace` 배지(⚡타이트/🌊슬로우) + 화자 태그
  - 한글 장면 요약 + 취향 태그 칩
  - **셀렉터**: 카드 우상단 `● OK / ✎ 수정` 토글 → 선택 상태가 `selections.json`에 실시간 저장(로컬 콘솔 서버, 메모리: reference-image-select-console 방식).
- **상단바**: 프레임/해상도 표시 · [OK 일괄] · [수정만 필터] · [본 생성으로 진행] 버튼.
- 출력은 **그 버전 폴더 안에** 저장: `storyboard_preview_{name}_480p_v{날짜}.html`.

```python
# system_v2/_build_storyboard_preview.py (개념 스케치 — 절대경로 하드코딩 금지, __file__ 기준 ROOT)
# for scene in scenes: thumb = base64(jpeg(resize(png, 480_frame))); card(scene, thumb)
# 셀렉터 상태는 fetch POST /select {scene, verdict} → selections.json append (review_console 서버 재사용)
```

### 16-3. 셀렉트 (사용자)
- 사용자가 브라우저에서 각 씬을 `OK/수정`으로 판정. `selections.json`이 STAGE 3의 "고화질로 갈 씬 / 먼저 고칠 씬"을 가른다.

> **규칙 3 준수:** 생성 이미지를 에이전트가 Read로 열지 않는다. 480p 프리뷰도 경로만 안내하고 사용자가 콘솔에서 본다.

**산출물:** 480p 전 씬 이미지 + `storyboard_preview_*.html` + `selections.json`.

## GATE S17 — 씬별 이미지 수정 · 모델 선택 UI

**왜:** 셀렉터에서 `수정`으로 찍힌 씬을, **씬 단위로 다시 잡고 모델도 고르게** 한다. (사용자 요구: "html 셀렉터 결과물을 바탕으로 씬 별로 이미지 수정을 할 수 있게 해주고, 모델도 선택할 수 있게")

### 17-1. 수정 콘솔 (프리뷰 HTML 확장 — `review_console/` 패키지 재사용)
`수정`으로 찍힌 카드를 펼치면 **수정 패널**이 뜬다:
| 컨트롤 | 옵션 |
|---|---|
| **모델(드롭다운)** | 나노바나나-라이트(480p 재초벌) · `nano_banana_2` · **`gpt_image_2`** · `seedream-4` · Magnific `imagen-nano-banana-2` |
| **해상도(드롭다운)** | 480p(초벌) · 1k · 2k |
| **화각(드롭다운)** | 하이 · 로우 · 사이드 · 더치 · OTS · 데마이CU · 인서트 (S21 화각 밸런스와 연동) |
| **수정 요청(입력창)** | 한글 자유 입력, **Enter=제출**(Shift+Enter 줄바꿈) |
| 상태칩 | 대기 → 처리중 → 완료 |

- **동작(브리지):** `file://` HTML은 직접 MCP 호출·파일쓰기가 막힘 → **로컬 서버 + 큐(revision_queue.jsonl) + 백그라운드 에이전트 워처** 3단 브리지(`review_console/` 그대로). Enter 제출 → 서버가 큐에 append → 워처가 해당 씬만 재생성 → `results.json` 갱신 → 카드 폴링 교체.
- 재생성 시 **선택 모델·해상도·화각 + 수정요청 + 규칙0[A] + DRAMA_IMG_ENHANCE**를 합쳐 호출.
- **덮어쓰기 금지:** 재생성은 새 버전 폴더에 저장, `results.json`이 최신을 가리킨다(규칙 2).

### 17-2. 모델 선택 가이드 (사용자에게 안내)
- **얼굴·인물 초벌 방향**: `nano_banana_2` 계열(일관성 강). **텍스트·정보·특수 구도**: `gpt_image_2`. **포토리얼·질감**: `seedream-4`/Magnific NB. **저비용 재확인**: 나노바나나-라이트.
- 단, **최종 인물 일관성은 STAGE 3의 캐릭터 시트 ref 락**에서 완성된다. 이 단계 수정은 '구도·미술 방향' 확정용.

**산출물:** 수정된 씬 초벌 + 씬별 확정 모델·화각 메모(STAGE 3 입력).

## GATE S18 — 전 씬 공통 미술 · 조명 UI (본 생성 직전)

**왜:** 진짜 생성 전에 **전 씬에 공통 적용할 미술·조명**을 한 번에 잠근다. (사용자 요구: "진짜 이미지를 생성하기 전에 전체 씬에 적용해야 하는 미술이나, 조명 같은 구체적인 것도 선택할수 있게 UI를 구현")

### 18-1. 전역 미술·조명 컨트롤 패널 (프리뷰 HTML 상단 '전역 설정' 탭)
아래를 **전 씬 공통 상수**로 고르고, 저장 시 `global_look.json`에 기록 → STAGE 3의 모든 프롬프트에 자동 주입.

| 그룹 | 컨트롤 | 옵션(예) |
|---|---|---|
| **룩 베이스** | 카메라·필름 | ARRI Alexa + 아나모픽 / 35mm 그레인 강도 / 소프트(비-임상) |
| **컬러 그레이드** | 전체 색조 | 틸앤앰버 · 저채도 느와르 · 크러시드 블랙 · 파스텔 · 웜 골든 · 콜드 블루 + **필름 스톡 룩**(웜 포트레이트/텅스텐 야경/블리치 바이패스/테크니컬러 — `06` [그레이딩 스톡], 프로젝트당 1개) |
