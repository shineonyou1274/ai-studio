# 영상 공모전 제작 에이전트 운영 규칙

3팀이 `기획 → 생성 → 검수` 순서로 협업한다. 앞 단계의 필수 산출물이 없으면 다음 팀이 임의로 대신 만들지 말고 이전 팀으로 돌려보낸다.

## 팀 구성

1. **기획팀 — 분석 + 기획**
   - 공모전 요강에서 참가조건·제출형식·심사기준·금지사항을 정리한다.
   - 유리한 영상의 특성을 분석하고 주제·메시지·콘셉트·타깃·차별점을 기획안으로 만든다.
   - 입력: `01_요강/`
   - 출력: `02_기획/기획안.md`
2. **생성팀 — 보드 + 이미지 + 영상**
   - 승인된 기획안을 씬별 스토리보드로 나눈다.
   - 씬마다 이미지 프롬프트를 작성하고, 이미지 승인 후 영상 프롬프트를 작성한다.
   - **스토리보드는 씬마다 실제 생성 이미지를 넣은 갤러리형 HTML로 만든다.** 이미지 생성이 전제이므로 **MCP(Higgsfield) 로드·연결이 스토리보드 작성보다 선행**되어야 한다.
   - Higgsfield MCP가 연결된 경우 이미지에서 영상 순서로 생성한다. **미연결이면 멈추지 말고** 프롬프트만 채운 텍스트 스토리보드(`스토리보드.md`)를 fallback으로 만들고 연결 필요를 보고한다.
   - 입력: `02_기획/기획안.md`
   - 출력: `03_스토리보드/`(연결 시 `.html` 갤러리 / 미연결 시 `.md`), `04_생성물/`
3. **검수팀 — 최종 점검**
   - 제출 규격·기획 의도·장면 흐름·심사기준 대응을 점검한다.
   - 수정 사항을 P0/P1/P2 우선순위로 정리하고 담당 팀에 반려한다.
   - 입력: `01_요강/`부터 `04_생성물/`까지
   - 출력: `05_검수/검수리포트.md`

## 필수 제작 워크플로우

콘텐츠를 만들 때는 항상 다음 순서와 확인 지점을 지킨다. AI가 모든 단계를 임의로 끝내지 않는다.

1. 스토리 방향을 **2~3안 제안**한다.
2. 사용자가 선택한 스토리를 **씬 단위로 분해**한다.
3. 씬 구성을 사용자에게 확인받는다.
4. 각 씬의 이미지 프롬프트를 다음 5단 구조로 작성한다.
   - `주제 - 행동 - 조명 - 분위기 - 카메라 구도`
5. 이미지를 생성하고 사용자의 확인을 받는다.
6. 승인된 이미지를 기준으로 영상 프롬프트를 작성하고 영상을 생성한다.
7. 다음 씬이나 다음 단계로 넘어가기 전에 사용자 확인을 받는다.

## 프롬프트 작성 규칙 (2026-10-22 소울체인지 2화 검수 반영)

- 영상 프롬프트에 **정지 유발어를 쓰지 않는다**: 멈춘다·굳어 있다·정자세·아무 말 없이·거의 고정·freeze·static·still. 대신 지속 미세동작(눈동자 이동, 호흡, 손가락, 천천히 내린다)을 쓴다.
- 5초 컷 하나에 행동은 **최대 2개**. 심리 묘사("영혼이 들어 있어서", "당황을 숨기려고")는 모델이 못 읽으니 쓰지 않고, 보이는 동작으로 바꾼다.
- 9:16에서 두 사람 이상이 대화하는 컷은 **측면·오버숄더**로 잡고 `no one looks at the camera`를 명시한다. 정면 나란히 세우면 카메라를 본다.
- 속말·DM·내레이션이 얹힐 컷은 `mouth stays closed, no speaking`을 명시한다.
- 말하는 인물이 있는 장면은 반드시 영상으로 생성한다. 스틸 줌으로 3초 이상 때우지 않는다.
- 소품은 카메라에 보이는 것만 지시한다(미디엄 샷에서 "종이의 빈칸을 본다"는 불가). 연속성(전날 결석인데 원고를 들고 있음)을 확인한다.
- 실제 사용한 이미지·영상 프롬프트는 전부 파일로 보관한다(`생성로그.md` 또는 `prompt_*.txt`).

## 검수 게이트 (필수)

- **Gemini 검수**: 컷 편집본(mp4)이 나오면 gemini.google.com(Argon)에 올려 "칭찬 없이 세게" 검수받는다. 점검 항목: 누가 누군지(정체성), 목소리 일관성, 정지 구간, 연속성, 타임코드별 지적, 업로드 가부 판정. 결과를 반영한 뒤에야 사용자에게 완성본으로 보고한다. 검수 전문은 파일로 저장한다.
- 시청자 역할(타깃 시청자, 편집자) 서브에이전트 검수를 병행한다.

## 확인 게이트

- **스토리 선택**: 사용자가 선택한 안만 발전시킨다.
- **씬 승인**: 승인된 씬 구성만 이미지 단계로 넘긴다.
- **이미지 승인**: 생성 이미지를 확인받기 전에는 영상 프롬프트를 작성하거나 영상을 생성하지 않는다.
- **진행 승인**: 사용자가 멈추거나 수정을 요청하면 다음 단계로 진행하지 않는다.

## 파일 규칙

- 원본 요강은 `01_요강/`에서 수정하지 않는다.
- 이미지와 영상은 각각 `04_생성물/images/`, `04_생성물/videos/`에 저장한다.
- 생성 파일은 `씬01_설명.png`, `씬01_설명.mp4`처럼 씬 번호를 접두어로 사용한다.
- 생성 상태와 실제 사용 프롬프트는 `04_생성물/생성로그.md`에 기록한다.
- Higgsfield MCP가 없으면 영상·이미지를 생성하지 않는다. 대신 프롬프트만 채운 텍스트 스토리보드(`03_스토리보드/스토리보드.md`)를 fallback으로 만들고 연결 필요 상태를 보고한다. 연결되면 같은 프롬프트로 이미지를 생성해 HTML 갤러리로 승격한다.
