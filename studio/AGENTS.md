# 소울체인지 제작 에이전트 운영 규칙

원본: `playbook/원본_공모전팀/AGENTS.md`(공모전용). 이 파일은 그 규칙을 시리즈 쇼츠용으로 옮긴 것입니다. **프롬프트 작성 규칙과 검수 게이트는 원본 그대로**이며, 입력·출력 위치만 회차 폴더에 맞췄습니다.

3팀이 `기획 → 생성 → 검수` 순서로 협업한다. 앞 단계의 필수 산출물이 없으면 다음 팀이 임의로 대신 만들지 말고 이전 팀으로 돌려보낸다. 단계별 세부 절차는 `playbook/drama_playbook_v2/`(드라마 플레이북 v2)를 따른다.

## 팀 구성

1. **기획팀 `planning-team` — 분석 + 기획** (플레이북 STAGE 1)
   - 입력: `series/README.md`(시리즈 바이블), 작가 규칙, 이전 회차
   - 출력: `projects/<회차>/02_기획/기획안.md`
2. **생성팀 `generation-team` — 보드 + 이미지 + 영상** (플레이북 STAGE 2~4)
   - **스토리보드는 씬마다 실제 생성 이미지를 넣은 갤러리형 HTML로 만든다.** 이미지 생성이 전제이므로 **MCP(Higgsfield) 로드·연결이 스토리보드 작성보다 선행**되어야 한다.
   - **미연결이면 멈추지 말고** 프롬프트만 채운 텍스트 스토리보드(`스토리보드.md`)를 fallback으로 만들고 연결 필요를 보고한다.
   - 입력: `02_기획/기획안.md` · 출력: `03_스토리보드/`, `04_생성물/`
3. **검수팀 `review-team` — 점검**
   - 쇼츠 규격·기획 의도·장면 흐름·연속성을 점검하고, P0/P1/P2로 정리해 담당 팀에 반려한다.
   - 출력: `06_검수/검수리포트.md`

## 필수 제작 워크플로우

콘텐츠를 만들 때는 항상 다음 순서와 확인 지점을 지킨다. AI가 모든 단계를 임의로 끝내지 않는다.

1. 스토리 방향을 **2~3안 제안**한다.
2. 사용자가 선택한 스토리를 **씬 단위로 분해**한다.
3. 씬 구성을 사용자에게 확인받는다.
4. 각 씬의 이미지 프롬프트를 다음 5단 구조로 작성한다. `주제 - 행동 - 조명 - 분위기 - 카메라 구도` (플레이북 규칙 0-[A] 프리픽스를 함께 붙인다)
5. 이미지를 생성하고 사용자의 확인을 받는다.
6. 승인된 이미지를 기준으로 영상 프롬프트를 작성하고 영상을 생성한다. (플레이북 규칙 0-[B] 프리픽스를 맨 앞에 둔다)
7. 다음 씬이나 다음 단계로 넘어가기 전에 사용자 확인을 받는다.

## 프롬프트 작성 규칙 (2026-10-22 소울체인지 2화 검수 반영)

- 영상 프롬프트에 **정지 유발어를 쓰지 않는다**: 멈춘다·굳어 있다·정자세·아무 말 없이·거의 고정·freeze·static·still. 대신 지속 미세동작(눈동자 이동, 호흡, 손가락, 천천히 내린다)을 쓴다.
- 5초 컷 하나에 행동은 **최대 2개**. 심리 묘사("영혼이 들어 있어서", "당황을 숨기려고")는 모델이 못 읽으니 쓰지 않고, 보이는 동작으로 바꾼다.
- 9:16에서 두 사람 이상이 대화하는 컷은 **측면·오버숄더**로 잡고 `no one looks at the camera`를 명시한다. 정면 나란히 세우면 카메라를 본다.
- 속말·DM·내레이션이 얹힐 컷은 `mouth stays closed, no speaking`을 명시한다.
- 말하는 인물이 있는 장면은 반드시 영상으로 생성한다. 스틸 줌으로 3초 이상 때우지 않는다.
- 소품은 카메라에 보이는 것만 지시한다(미디엄 샷에서 "종이의 빈칸을 본다"는 불가). 연속성(전날 결석인데 원고를 들고 있음)을 확인한다.
- **장면·앵글·카메라를 다채롭게 (사장님 결정 2026-10-26: "쇼츠는 장면과 앵글 카메라가 다채로워야 해. 한 곳만은 안 돼. 현란하게").**
  - 같은 장소·같은 앵글 컷을 연달아 두지 않는다. 한 화 안에서 장소·샷 크기(익스트림 클로즈업~와이드)·앵글(로우·하이·측면·오버숄더·탑)을 섞는다.
  - 카메라 무빙을 컷마다 정한다: 돌리 인, 아크(인물 둘레를 반원으로 돎), 트래킹, 휩 팬, 크래시 줌, 핸드헬드. 고정 카메라는 이유가 있을 때만.
  - 인서트 샷(손·폰·소품·발 클로즈업)을 화마다 2개 이상 넣는다.
  - 가끔 조명으로 감성을 더한다: 역광(창가 실루엣, 머리카락 빛 테두리), 노을빛, 블라인드 줄무늬, 형광등 깜빡임.
  - 단, 컷당 행동 최대 2개·정지 유발어 금지·대화 컷 측면/오버숄더 규칙은 그대로 지킨다. 카메라 무빙은 행동 수에 넣지 않는다.
- **편집으로 살리는 방법 (5화 v1→v8, 사장님 2026-10-27: "이 정도면 되겠어. 지금 한 것만큼만 해도 잘했어. 기억해").** 다시 뽑기 전에 아래를 먼저 쓴다.
  - 얼굴이 늘어나거나 뭉개지기 직전의 깨끗한 프레임에서 화면을 멈추고, 흰 번쩍임·펀치 인·흔들림·만화 집중선(얼굴 위에는 선 없음)을 코드로 얹는다. 고함·대사는 멈춘 화면 위에 얹는다.
  - 입이 대사와 안 맞으면 교차 편집: 말하는 얼굴은 입이 맞는 순간만, 나머지는 듣는 사람 반응·뒤통수·손짓. 말하지 않는 인물이 입을 움직이면 입 다문 프레임을 멈춰 천천히 다가간다.
  - 녹음이 입보다 길면 음높이를 유지한 채 1.1~1.3배 빠르게 줄여 입 움직임 길이에 맞춘다(크레딧 0).
  - 뭉개진 손·AI 표시·옆 인물은 1.6배 안에서 확대·자르기로 화면 밖으로 뺀다. 그 이상은 컷을 줄이고 다른 화면으로 덮는다.
  - 멈춘 배경 인물은 배경을 강하게 흐리거나 컷을 짧게.
  - 일어선 뒤 앉은 그림 금지 같은 동선 연속성을 컷 순서로 지킨다. 그림이 없으면 상대 반응 컷으로 덮는다.
  - 화면에 없는 동작(친구가 떠남)은 휩 팬 + 효과음(의자·발소리)으로 알린다.
  - 인물의 속뜻을 예능 해설 자막 한 줄로 보탠다(예: "(들킬까 봐 괜히 버럭)"). 대사만큼 크게, 얼굴 옆 빈 곳.
  - 배경음은 외부 음원 없이 코드로 합성(초침·낮은 울림·현 떨림, -28 LUFS, 대사 아래 15dB 낮춤)하고, 웃음 포인트 직전·직후에 뚝 끊어 정적을 만든다.
  - 속마음 목소리 규칙(속마음 = 영혼 목소리 + 울림)은 음높이를 재서 확인한다. Gemini가 화면 속 얼굴 때문에 잘못 듣는 일이 잦으므로 잰 값으로 판단하고 사장님 청취로 확정한다.
  - 대사가 흐름을 끊으면 녹음을 새로 하지 말고 순서부터 바꿔 본다(5화: 말실수 → 의심 → "헐… 설마" → 들킬까 봐 반격 → 고지식 끝).
- 실제 사용한 이미지·영상 프롬프트는 전부 파일로 보관한다(`생성로그.md` 또는 `prompt_*.txt`).

> 플레이북과 부딪칠 때: 플레이북 규칙 0의 `still`은 "정지"가 아니라 문장 속 일반 단어로 나올 수 있다. 영상 프롬프트 본문에서는 위 정지 유발어 금지가 이긴다. 플레이북의 "정면 아이레벨 배제"와 위 "측면·오버숄더" 규칙은 같은 방향이다.

## 검수 게이트 (필수)

- **Gemini 검수**: 컷 편집본(mp4)이 나오면 gemini.google.com(Argon)에 올려 "칭찬 없이 세게" 검수받는다. 점검 항목: 누가 누군지(정체성), 목소리 일관성, 정지 구간, 연속성, 타임코드별 지적, 업로드 가부 판정. 결과를 반영한 뒤에야 사용자에게 완성본으로 보고한다. 검수 전문은 `06_검수/gemini_검수.md`에 저장한다.
  - 편집장이 브라우저로 직접 올릴 수 없는 환경이면, 사용자에게 업로드를 요청하고 받은 전문을 저장한다.
- 시청자 역할(타깃 시청자, 편집자) 서브에이전트 검수를 병행한다. → 검수팀 `review-team`

## 확인 게이트

- **스토리 선택**: 사용자가 선택한 안만 발전시킨다.
- **씬 승인**: 승인된 씬 구성만 이미지 단계로 넘긴다.
- **이미지 승인**: 생성 이미지를 확인받기 전에는 영상 프롬프트를 작성하거나 영상을 생성하지 않는다.
- **진행 승인**: 사용자가 멈추거나 수정을 요청하면 다음 단계로 진행하지 않는다.
- **크레딧 승인**: 생성 전 비용 승인 파일(`04_생성물/approvals/`)이 `approved`여야 한다. (`CLAUDE.md` 4절)

## 파일 규칙

- 시리즈 확정 자산(캐릭터 시트, Voice Sheet)은 수정하지 않는다.
- 이미지와 영상은 각각 `04_생성물/images/`, `04_생성물/videos/`에 저장한다.
- 생성 파일은 `씬01_설명.png`, `씬01_설명.mp4`처럼 씬 번호를 접두어로 사용한다. 고친 결과는 덮어쓰지 않고 `_v2`를 붙인다.
- 생성 상태와 실제 사용 프롬프트는 `04_생성물/생성로그.md`에 기록한다.
- Higgsfield MCP가 없으면 영상·이미지를 생성하지 않는다. 대신 텍스트 스토리보드(`03_스토리보드/스토리보드.md`)를 fallback으로 만들고 연결 필요 상태를 보고한다.
